Contiguous Allocation, Paging, and Segmentation

Contiguous Allocation

In memory management, Contiguous Allocation is a method where each process is allocated a single continuous block of memory. All the instructions and data for the process reside in one uninterrupted region of memory, making it straightforward for the system to find and access. However, it can lead to issues like external fragmentation over time because free memory gets scattered, leaving unusable small holes between allocated segments.

Real Life Analogy:
Imagine placing books on a shelf. If each process is a book, you must place the book in one continuous space without gaps. If a new book doesn't fit in the leftover space, you have to rearrange or find another continuous empty space. This can be cumbersome if you constantly need to adjust your books (processes).

How Contiguous Allocation Works

  1. Memory Reservation: The operating system finds a free block of memory large enough to hold the entire process.
  2. Loading the Process: The process’s code and data are placed in that contiguous memory region.
  3. Execution: The CPU accesses memory locations sequentially without complex calculations, ensuring fast access.
  4. Deallocation: When the process completes, the entire block is freed, potentially leaving gaps.

Advantages of Contiguous Allocation

  1. Simple to implement and manage, making memory addressing straightforward.
  2. Fast access to process instructions due to direct sequential memory layout.

Disadvantages of Contiguous Allocation

  1. External fragmentation occurs as processes are loaded and removed, leaving small unusable gaps.
  2. Finding a suitable free memory block for a new process can be time-consuming as the system grows busy.

Paging

Paging is a memory management technique that avoids the need for continuous memory allocation. Instead, the process’s memory is divided into fixed-size blocks called pages, and the main memory is divided into frames of the same size. The process’s pages can be placed into any available frames, regardless of their positions, allowing for more flexible memory use and reducing external fragmentation. Paging uses a page table to map logical addresses to physical frames.

Real Life Analogy:
Consider a thick reference book split into numbered pages. These pages can be arranged in different places on shelves (frames) in a library. You have an index (page table) that tells you where each page of the book is located. Even though the pages might not be next to each other physically, you can still read the book using the index.


How Paging Works

  1. Division into Pages: The process is split into equal-sized chunks called pages.
  2. Frames in Physical Memory: The main memory is divided into frames of the same size as pages.
  3. Page Table Mapping: Each page of the process is placed into any available frame. A page table keeps track of which frame holds which page.
  4. Address Translation: When the CPU references a memory address, it uses the page table to convert the logical page number into the corresponding frame number.

Advantages of Paging

  1. Eliminates external fragmentation, as memory is allocated in uniform frames.
  2. Processes do not need continuous memory, making allocation more flexible.
  3. Simplifies memory management by dealing with fixed-sized pages and frames.

Disadvantages of Paging

  1. Involves additional overhead due to address translation using a page table.
  2. Internal fragmentation can occur if a page does not fully use all frame space.
  3. Accessing memory might be slightly slower due to the extra step of looking up the page table.

Segmentation

Segmentation is another memory management approach where a process is divided into logical segments based on the program’s structure, such as code, data, and stack segments. Unlike paging, segments vary in size, reflecting the logical divisions of a program’s memory. Each segment has its own segment number and offset. A segment table is used to map these segments into physical memory. Although it provides a more natural way to organize memory, segmentation can lead to external fragmentation over time.

Real Life Analogy:
Think of working on multiple projects stored in separate folders on your computer. Each folder (segment) contains all files related to a particular aspect (like code files in one folder and documents in another). The folder sizes differ based on the content. Just as you navigate folders to find specific files, the OS uses a segment table to find the location of each segment in memory.

How Segmentation Works

  1. Division into Segments: The program is divided into segments based on logical divisions (e.g., code segment, data segment).
  2. Segment Table Mapping: Each segment is assigned a segment number and recorded in a segment table, which stores the base address and length of that segment.
  3. Address Translation: When a memory reference is made, the CPU uses the segment number and offset within that segment to locate the correct memory address.

Advantages of Segmentation

  1. Reflects the logical structure of programs, making memory management more intuitive.
  2. Different segments can grow independently (e.g., stack or heap).

Disadvantages of Segmentation

  1. External fragmentation can occur as segments vary in size and move around memory.
  2. Finding suitable holes for segments can become challenging as memory usage increases.

Key Differences between Contiguous Allocation, Paging, and Segmentation

  1. Contiguous Allocation: Requires continuous memory blocks for each process, simple but prone to external fragmentation.
  2. Paging: Uses fixed-size pages and frames, eliminating external fragmentation but introducing a page table for address translation.
  3. Segmentation: Divides memory into variable-sized segments based on program structure, more intuitive logically but susceptible to external fragmentation.

In essence:
  • Contiguous allocation is like putting all your belongings in one continuous space.
  • Paging breaks memory into uniform chunks for flexible placement.
  • Segmentation divides memory based on logical segments, closer to how programmers view their programs.
