Disk Scheduling Algorithms

Disk scheduling algorithms are critical mechanisms in Operating Systems designed to decide the order in which the disk drive will serve the pending I/O requests. These algorithms ensure efficient and fair use of the disk, minimizing the total seek time, reducing latency, and improving overall system performance.

Real Life Analogy: Imagine a librarian retrieving books for multiple readers. Each reader requests a different book from a large bookshelf (your disk). The librarian (the disk head) can choose which request to fulfill first. If the librarian moves back and forth randomly to pick books, it takes much longer (more seek time). By using a proper strategy (like a disk scheduling algorithm), the librarian can reduce the total walking time (seek time) and serve readers more efficiently.
Disk scheduling is all about how we decide to move the disk arm (which is like the librarian’s position) across the platter to serve requests optimally. Each algorithm comes with its own strategy, trade-offs, advantages, and disadvantages.

1. First-Come, First-Served (FCFS)

FCFS is the simplest disk scheduling algorithm. It processes requests in the exact order they arrive, with no reordering or prioritization.

How it Works:
  1. The disk queue receives requests in a certain order (e.g., requests for tracks 40, 180, 10, etc.).
  2. The disk head moves to serve each request sequentially without any optimization.


Advantages:
  1. Simple to implement and understand.
  2. Fair, as requests are served in the order they appear.
Disadvantages:
  1. Not optimal for minimizing total seek time.
  2. Can cause long waiting times if a request far away is followed by one very close.

2. Shortest Seek Time First (SSTF)

SSTF selects the request with the shortest seek distance from the current head position. This means the algorithm chooses the closest track request next.

How it Works:
  1. Check all pending requests and find the one closest to the current head position.
  2. Serve that request next, then repeat the process.


Advantages:
  1. Significantly reduces overall seek time compared to FCFS.
  2. Often improves throughput.
Disadvantages:
  1. Can lead to starvation of requests at the ends of the disk if new requests keep appearing close to the head.
  2. Not strictly fair, as some requests might wait longer.

3. SCAN (Elevator) Algorithm

Also known as the Elevator algorithm, SCAN moves the disk head in one direction (e.g., from the outer edge to the inner edge), fulfilling all requests along the way, and then reverses direction when it reaches the end of the disk.

How it Works:
  1. The head moves in a linear fashion across the disk (like an elevator going up and down).
  2. Once it reaches an end, it reverses and continues serving any pending requests in the opposite direction.



Advantages:
  1. Provides a more uniform wait time than FCFS or SSTF.
  2. Reduces the chances of starvation since the head eventually reaches all requests along the way.
Disadvantages:
  1. Long waiting times for requests just missed after the head turns around.
  2. Not always optimal in minimizing total seek time compared to some more advanced algorithms.

4. C-SCAN (Circular SCAN)

C-SCAN modifies SCAN by treating the disk as a circular list. Once it reaches one end, the head immediately jumps back to the start of the disk and continues from there, serving requests as it goes.

How it Works:
  1. The head scans from the lowest track to the highest track.
  2. Upon reaching the highest track, it jumps directly to the lowest track without serving requests in the opposite direction.
  3. This ensures a more predictable wait time distribution.



Advantages:
  1. Uniform wait time since each request waits at most one full scan cycle.
  2. More consistent performance compared to SCAN, especially in heavy load situations.
Disadvantages:
  1. Sometimes less optimal than SSTF for specific workloads.
  2. Still involves overhead in scanning through empty regions of the disk.

5. LOOK and C-LOOK Algorithms

LOOK and C-LOOK are variations of SCAN and C-SCAN. Instead of scanning all the way to the ends of the disk, the head only travels as far as the farthest request in each direction.

How it Works (LOOK):
  1. Similar to SCAN, but the head “looks” ahead for the last request in its path and only goes that far.
  2. Then it changes direction, ensuring no unnecessary travel to tracks without requests.

How it Works (C-LOOK):
  1. Similar to C-SCAN, but it only travels to the last request in the direction it’s going, then jumps back.
  2. This reduces unnecessary full end-to-end travel.



Advantages:
  1. More efficient than SCAN and C-SCAN since there is no wasteful movement to extreme ends without requests.
  2. Reduced overall seek times compared to their basic counterparts.
Disadvantages:
  1. Still might not always outperform SSTF in certain scenarios.
  2. Slightly more complex to implement compared to SCAN and C-SCAN.

Choosing the Right Algorithm

Each algorithm has its own use case:
  1. FCFS: Simple, but not optimal.
  2. SSTF: Great for reducing seek time but can cause starvation.
  3. SCAN & C-SCAN: Good for uniform waiting times and prevent starvation effectively.
  4. LOOK & C-LOOK: More efficient versions of SCAN and C-SCAN with less travel overhead.

The choice depends on the system’s priorities: fairness, minimal seek time, or predictable response. By understanding these algorithms, Operating Systems can efficiently manage disk usage, ensuring a balance between performance and fairness.
